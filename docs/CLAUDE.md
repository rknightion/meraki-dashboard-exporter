<system_context>
Documentation source for the Meraki Dashboard Exporter. This is a **Zensical** site whose
repository-owned input is `docs.toml`. The site is not built in this repo: pushes to `main`
touching `docs/**`, `docs.toml`, or `scripts/**` trigger
`.github/workflows/trigger-docs-sync.yml`, which fires a `repository_dispatch` into
`m7kni/m7kni-net-site`. That hub generates the Zensical configuration and presentation, then
builds and publishes the site.
</system_context>

<critical_notes>
- **Eight committed artefacts are auto-generated by `scripts/generate_*.py` — NEVER hand-edit them.** Regenerate with `just gen` (or the individual `just docs-*` recipes) after any change to collectors/config/metrics/endpoints code, then commit the regenerated output:
  - `docs/config.md` ← `scripts/generate_config_docs.py`
  - `.env.example` ← `scripts/generate_env_example.py`
  - `charts/meraki-dashboard-exporter/values.yaml` and `charts/meraki-dashboard-exporter/templates/configmap.yaml` ← `scripts/generate_helm_config.py`
  - `docs/scaling-guide.md` ← `scripts/generate_scaling_capacity_docs.py`
  - `docs/metrics/metrics.md` ← `scripts/generate_metrics_docs.py`
  - `docs/collectors/reference.md` ← `scripts/generate_collector_docs.py`
  - `docs/reference/endpoints.md` ← `scripts/generate_endpoints_docs.py`
- **No "DO NOT EDIT" banner is written into these files** — the generators overwrite silently with no header comment, so this list (and cross-checking against `scripts/CLAUDE.md`) is the only way to know. If you hand-edit one, the next `just gen` silently wipes your change.
- **`docs/changelog.md` is also generated, but by release-please, not by a `scripts/generate_*.py` script.** `release-please-config.json` sets `"changelog-path": "docs/changelog.md"` — it's rewritten by the release-please GitHub Action on every release PR. Don't hand-edit it either.
- **Site nav is defined in `docs.toml`'s `[[site.nav]]` entries**, not in any file under `docs/`. Adding a new page requires adding it there too; the documentation hub consumes those entries when generating the site presentation.
- **`.meta.yml` files** (`docs/.meta.yml`, `docs/collectors/.meta.yml`, `docs/metrics/.meta.yml`) supply per-section SEO/meta defaults (title, description, tags, social) to the site build — they apply to every page in that directory that doesn't override the corresponding frontmatter key.
- Most hand-written pages use YAML frontmatter (`title`, `description`, `tags`, `hide`) — follow the existing pattern in a neighboring file rather than inventing a new frontmatter shape.
</critical_notes>

## STRUCTURE
- `docs.toml` (repo root) - repository-owned site metadata and navigation input; the `m7kni/m7kni-net-site` hub generates the Zensical configuration, presentation, and build from it.
- `docs/index.md`, `getting-started.md`, `config.md` (generated), `deployment-operations.md`, `security.md`, `scaling-guide.md`, `integration-dashboards.md`, `changelog.md` (generated by release-please) - top-level hand-written pages (config.md excepted)
- `docs/api-call-audit.md` - point-in-time hand-maintained audit doc of Meraki API calls (dated entries, not regenerated by tooling)
- `docs/collectors/` - `index.md` (hand-written overview) + `reference.md` (generated) + `.meta.yml`
- `docs/metrics/` - `index.md` (hand-written landing page), `overview.md` (hand-written: categories/tiers/label conventions), `metrics.md` (generated) + `.meta.yml`
- `docs/reference/` - `endpoints.md` (generated HTTP endpoint table)
- `docs/observability/` - `otel.md`, `tracing.md` - hand-written OpenTelemetry/tracing docs
- `docs/development/` - `release-process.md` - hand-written, describes the release-please flow
- `docs/extending-collectors.md` - hand-written contributor guide for adding new collectors
- `docs/includes/abbreviations.md` - glossary snippet auto-appended to every page by the site build
- `docs/overrides/main.html` - Zensical/Material theme template override used by the site build
- `docs/javascripts/`, `docs/stylesheets/` - theme extra JS/CSS used by the site build
- `docs/assets/social-card.png` - social preview image referenced from frontmatter `image:` keys
- `docs/404.md`, `500.md`, `tags.md`, `robots.txt`, `.nojekyll` - special/static pages for the built site, hand-maintained but rarely touched
</file_map>

<paved_path>
## REGENERATING DOCS AFTER A CODE CHANGE
```bash
just gen             # runs all generators in order
just docs-config     # config.md only
just docs-env        # .env.example only
just docs-helm       # Helm config regions only
just docs-scaling    # scaling guide region only
just docs-metrics    # metrics/metrics.md only
just docs-collectors # collectors/reference.md only
just docs-endpoints  # reference/endpoints.md only
```
Run `just gen` (or the specific recipe) any time you add/change a collector, a Pydantic config field, a Prometheus metric, or a FastAPI endpoint, then commit the generated diff alongside your code change — reviewers rely on these files being in sync with the code.

## ADDING A NEW HAND-WRITTEN PAGE
1. Create the `.md` file under the appropriate `docs/` subdirectory with YAML frontmatter matching sibling pages.
2. Add it to the `[[site.nav]]` entries in repository-owned `docs.toml`; the documentation hub
   uses that input when generating the site presentation.
3. If it belongs to a section with a `.meta.yml`, no per-page meta is required unless you need to override a default.
</paved_path>

<fatal_implications>
- **NEVER hand-edit generated documentation** - `docs/config.md`, `docs/metrics/metrics.md`, `docs/collectors/reference.md`, `docs/reference/endpoints.md`, and the generated regions in `docs/scaling-guide.md` are silently overwritten by `just gen` with no warning banner in the file itself.
- **NEVER hand-edit `docs/changelog.md`** - owned by release-please via `release-please-config.json`.
- **NEVER assume this is MkDocs** - the repository-owned site input is `docs.toml`; the
  documentation hub owns the generated Zensical configuration, presentation, and build, and its
  plugin/theme behavior differs from vanilla `mkdocs-material`.
</fatal_implications>
